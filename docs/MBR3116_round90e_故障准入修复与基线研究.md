## 2. 新触摸、保持和故障的分阶段契约

| 阶段 | 本轮要求 | 故障处理 |
|---|---|---|
| OFF→ON 或尚未完成差值验证 | 本轮有效原生 BUTTON_STAT，加本轮成功、SYNC一致、范围0..255的差值读组；保留原有幅值/邻格/确认规则 | 必要 DIFF 失败或越界不能推进确认；快速路径及邻格不能豁免 |
| 已准入且上一帧输出 ON | 本轮有效 BUTTON_STAT；保留原有持续 ON 不额外读取 DIFF 的优化 | 原生状态无效或过龄才进入对应通道故障保持 |
| 证据年龄 | 所有本轮验证读取结束，在同一主机时刻复核各片 BUTTON_STAT 从读开始到该时刻 ≤15ms | 较晚芯片的延迟不能授权较早过龄状态；故障掩码覆盖该片 |
| 故障保持 | 只能继承上一帧已 ON；从首次失败所需读操作开始计时，经过时间 <50ms | 不刷新确认、dip、sticky或拉伸期限；到期在下一次处理时释放并清空旧凭据 |
| 健康恢复 | 正常证据恢复后沿既有规则处理；实际输出已经 OFF 时强制重新读取差值 | 验证缓存仍在50ms内也不能授权失败后的新 ON |

**范围边界：同片另一新按键触发整组 DIFF 读取失败，只阻止需要该组差值准入的通道。已经准入、仍有有效且及时 BUTTON_STAT 的 ON 可持续超过50ms；本轮不提供全片任意 DIFF 失败后50ms统一释放保证。** 合格原生 ON 持续但当前 DIFF 很低的历史盲点同样保留。这是为保留连续触摸响应而采取的阶段契约，不能声称持续 ON 每帧都重新取得 DIFF。

实现限于 Core0 触摸整理，复用原来的 Pico SDK I2C、时钟、总线锁和 round90d 同步差值入口。每片差值仍最多两组、底层 wake NACK 最多三次；没有新增等待窗口或配置协议字段。采用独立 active 位，故障开始时间0、32位时间回绕和模式切换都有覆盖。SYNC只检验差值组内部一致，另读的BUTTON_STAT不保证来自同一芯片扫描时刻。

15ms是本函数内原生状态的主机年龄上限；50ms是故障判定期限。两者都不等于物理触板到 HID 的最大延迟保证，后续 ToF/USB、调度间隔与当前阻塞读仍需计入。

## 3. 官方机制研究和排除的方案

MBR 的普通按钮 DIFF 是归一化结果，超过255截断，不能直接当 RAW−BASE。AN90071要求先处理饱和再设置阈值；当前已400fF，继续提高软件门限不能恢复丢失的信息。NT控制高于基线的更新停止，NNT/LBR用于低于基线的复位，改变基线跟踪可能同时吸收慢触或长按。原厂建议避免无依据的override。[AN90071 §6.2.2–6.2.3](https://assets.infineon.com/is/content/infineon/infineon/row/public/documents/30/42/infineon-an90071-cy8cmbr3xxx-capsenser-design-guide-applicationnotes-en.pdf)

`BUTTON_LBR=0x1F`、`BUTTON_NNT=0x20`、`BUTTON_NT=0x21`分别含bit7 override与低7位参数；不能用一套“关闭ATH”操作声称全部SmartSense或基线自动行为关闭。具体参数需依官方寄存器和实验依据解释。[MBR Registers TRM](https://www.infineon.com/assets/row/public/documents/30/57/infineon-cy8cmbr3xxx-capsense-express-controllers-registers-trm-additionaltechnicalinformation-en.pdf)

MPR对照也需修正表述：源码 NHDT=1、NCLT=16、FDLT=255 的注释称“冻结”，但 AN3891 将 FDL=255解释为减慢滤波，并非单凭此值确认禁用。MPR数据手册给出 CL=01 的明确基线跟踪禁用接口；本树的具体效果尚需现场寄存器和基线变化确认。本轮不改已有可用 MPR 行为，亦不把源码注释当无悬空机理的证明。[NXP AN3891](https://www.nxp.com/docs/en/application-note/AN3891.pdf)、[MPR121 Datasheet §5.11](https://www.nxp.com/docs/en/data-sheet/MPR121.pdf)

因此没有部署基线吸收、超255门限、邻格平顶拒绝或新斜率判据。旧同255瞬时向量、四指平顶和慢触反例仍有效；没有取得新的可分输入前，换规则名字或全面重写无法证明根治。单格 RAW/BASE 诊断需选择传感器并等刷新，不假设能无成本同时读取全板RAW；ToF仍只负责Air。

## 6. 下一阶段安排

1. **beta10主观回归已完成**：用户反馈手感正常、隔空仍存在。保持此版作为已回归的必要质量处理基线，继续区分读取故障与正常测量下的接近误触。
2. **取得MPR现场对照后确定机制**：读回真实CONFIG1/2、ECR/CL、触摸/释放阈值、基线滤波、电流/充电时间及AutoConfig状态；再对齐空闲/接近/接触/长按原生滤波值、基线和实际HID。需要换回MPR时再与用户协调，当前不自动要求拆装。
3. **MBR仅提出一个有新增依据的实验**：先单通道诊断RAW/BASE变化与DIFF饱和的关联，检验是否存在未截断且响应及时的新信息，再决定能否进入在线影子判据。诊断选择和等待明确记入时序，动作确认不等价精确接触时刻。
4. **电气路径按证据触发**：原理图/模块料值核对CMOD、去耦、供电和回流，照片不作为料值/电气合规证明；没有物理屏蔽连接不启用Shield作软件根治。

任一候选先冻结规则再覆盖慢触、多押和slide反例，达不到可分裕量或响应要求就保留MPR可用方案并停止同类调参。本轮只推进可审核的必要质量处理，最终抗悬空问题仍未解决。
