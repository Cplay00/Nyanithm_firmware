# round90n：MPR有效读取与故障准入

2026-10-04。阶段B第二项，beta13/BID round90n，在已提交的round90m之上，独立构建/提交；仅系统枚举COM6身份，未打开串口/发送命令/刷机。

## 实际问题与修复

旧`readRegisters()`仅判断负数；标量重试忽略再次返回数，脏缓冲可进入数值。旧MPR模拟读取为0后保留raw ON，虽没有增加verifiedCount，共享touchCount仍能推进；输出OFF后保留验证凭据还可能跳过新模拟证据。生产代码注入短读/NACK/脏缓冲及连续故障复现这些路径；它们是可靠性风险，未证明是round90l第8条上半区断续或MBR隔空的物理原因。

驱动继续用现有Pico SDK截止时间/事务锁/repeated START入口，没有换I2C抽象或修改SDK/vendor。按[SDK返回计数接口](https://www.raspberrypi.com/documentation/pico-sdk/hardware.html#group_hardware_i2c)及本机SDK2.2.0头文件检查精确长度。bulk仍一次；标量最多两次、一次50us等待；每次失败清空接收窗。新bool接口区分有效零与故障，滤波字段按[NXP原生10位格式](https://www.nxp.com/docs/en/data-sheet/MPR121.pdf)检查保留位，基线读回高8位左移2，状态屏蔽到12个按钮。不将独立的状态/滤波/基线事务描述为原生同时采样。

MPR输出原先OFF的lane需要本轮合法模拟证据；持续ON保留既有省读优化。失败不能经原生位、邻格或fast path推进确认，也不算“弱信号”计数。恢复重试采取原有保守档位，不授予首次强触豁免。有效不足门限仍按原规则拒绝。逐键/全局继承/floor4、正常确认/迟滞/拉伸/映射保持；待确认或已释放后重入会增加所需的模拟读取，实际时序需验收，不能称整个健康扫描成本逐字节相同。

三片状态先读，全部模拟读取后统一核对从各片状态读取开始的主机年龄：`<=15ms`可用，`>15ms`屏蔽整片。本限值是主机证据政策，不是芯片扫描编号、接触到HID延迟或新原厂要求。

复用原MBR故障helper并仅改成通用名称。状态失败影响整片、模拟失败影响该lane；故障只继承上一完成帧ON，不刷新确认或拉伸时间。连续故障从该片首个故障轮的状态读取开始计时，`<50ms`保持，完成扫描判断`>=50ms`清凭据释放，支持起点0及回绕。**故障期间Core0可能被截止时间I2C调用阻塞，旧完成帧仍可被HID读取；50ms不是任意总线阻塞下的物理硬实时释放承诺。** 这里没有完成全设备最坏耗时测量，也没有中途发布异步释放。
