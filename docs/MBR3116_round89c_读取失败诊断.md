# round89c 读取失败诊断

承接 [round89b 实测与路线](MBR3116_round89b_实测与固件寄存器路线.md)。此前轻触记录有10帧出现B1显示255、C0硬件位ON而最终输出OFF；命令之间有时间差，压力缓存也会在读取失败后保留，因此尚不能归因。

## 固件变更

`1.6.6-beta2 / BID=round89c`仅增加诊断计数，不改变门限、扫描周期、重试、失败拒绝或触摸保持策略。Core0每次调用连续门控的`readDifferenceCounts()`最终失败时计一次，包含传输失败或两次SYNC校验未通过。内部重试成功、缓存复用、低信号、原生触摸OFF不计数。计数跨profile变化保留，重启归零，u32自然回绕。

既有C1仍为528字节，原保留的偏移36–39返回上述小端u32。Core1一次读取后写入局部报告，多包发送期间不重复读取；ARM对象确认变量4字节对齐、读写为单字指令。配置结构128字节、API 0x10、CFG_SET双写及3116配置块保持原样。

这是全芯片累计计数，不覆盖BUTTON_STAT读取失败、缓存超龄，也不标记具体电极。只能在时间窗内排查关联，不能凭一次计数增加断定某格断触原因。

## 离线验证

- 改前及改后迁移测试均138/138。
- 抽取实际生产触摸函数、驱动及门控：34/34场景、6479断言，覆盖失败只计一次、缓存不重复计数、开关保留计数、重试成功不计数及u32回绕。
- 抽取实际HID/B1/C0/C1代码：18/18场景；C1偏移、小端值、528字节总长、64字节分包时快照及相邻字段均通过。
- 独立只读复核无阻断问题。首次新增场景中的旧零legacy读取断言与临时关闭profile步骤矛盾，已改为禁用后记录基准并确认重新启用后不再增加；最终测试全过。
- Pico SDK 2.2.0 / ARM GCC 14.2.1 Release新目录构建通过。UF2 186880字节，SHA-256 `726DAFC39FCFF28526C2534E75644E21B4C1091D38E60C1B05D2DC1DF52ACB88`。

源码、前版UF2及面板备份：工作区`_dev_archive/round89c_before_20261001/`，基线提交`5168a07`。主机刷写脚本只刷RP2040 UF2并读回配置，不执行0xBA或写3116 NVM。

## 实机核对

已通过现有0xBB/0xA5路径在COM6设备上刷入，并回读`NYANFW1;1.6.6-beta2;hw_v1;BID=round89c`。刷前及刷后控制器128字节、0x40/0x41/0x42配置块均逐字节相等；原profile仍为Z=0/F=255/ON=70%/OFF=50%，对应179/127，RAW=0。没有执行0xBA、配置保存或写3116 NVM。设备配置备份位于工作区`_dev_archive/round89c_device_before_20261001/`。

最初主机脚本要求INFO_UF2包含RP2040，未识别实际说明中的`Model: Raspberry Pi RP2 / Board-ID: RPI-RP2`，在复制UF2前停止。已用Windows卷标及USB VID 2E8A/PID 0003确认E盘，修正为原生Board-ID后恢复同一次刷写；刷后串口恢复和版本核对均成功。不是固件刷写校验失败。

普通模式12.043秒内获取239组C1/B1/C0；C1固定528字节，失败累计16→171（增加155），滑条输出均零。姿势未要求用户保持，**这不是无接触验收**；累计计数有效证明运行时有读取失败，尚未确定传输还是SYNC原因，也不能将先前10帧断触全部归因于它。原始事务及时间保存在工作区`_dev_tools/round89c_live_20261001/uncontrolled_probe.json`，刷写与回读汇总见[实机JSON](MBR3116_round89c_刷写与诊断_20261001.json)。
