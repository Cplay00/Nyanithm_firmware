# round90t：同套件隔空触发的减轻计划与首轮执行

日期：2026-10-05。范围：主维护树 `Nyanithm_firmware_hw_v1`；不改硬件、不采用ToF触板裁决。规划基底HEAD `296610c`。本轮执行的是官方接口核查、历史数据回放和离线筛选工具；没有新固件部署或真机动作采集。

## 1. 当前判断

**可以继续降低部分误触，但目前没有证据支持在保留轻触、慢触、多押和滑动的同时，用现有MBR信号保证零隔空。先检查可分信号余量，再选择局部调整，比继续提高全板门限更有依据。**

用户最初描述互换MPR121/MBR3116后现象相近，随后明确补充：**“同一套件中 MBR 明显触发，MPR 几乎不触发”**；MPR手掌距表面估计3mm，diff最高约12–16。本计划按这一补充确定排查顺序，原始两次描述一并保留，不把最初“基本一致”当作已经完成的严格芯片等效对照。

这使“芯片测量/调谐与同一套件电气条件的组合”优先于“RP2040主控PCB单独决定隔空”。共享走线、层叠、供电、回流路径依然可能参与；两芯片的量程、自动调谐、基线和原生阈值不同，互换也可能改变启动校准与软件分支。现有实测有参考价值，尚不能将具体小板元件、铜层或某段算法判定为唯一根因。

MPR的12–16是用户观察值，目前缺原始读取、逻辑格、原生/页面尺度、配置与轻触下界。仓库既有报送支持MPR×2以及原始会话，不能默认当前页面是哪一种；两芯片counts也不能作倍率比较。若MPR目前已符合游戏体验，优先保留它的设置。若当前装的是MBR，则沿MBR路线推进，不把换芯片当作本计划的硬件免改方案。

## 2. 原厂接口对解决空间的限制

| 原厂事实 | 本次处理 |
|---|---|
| 电容感测检测的是电容变化；覆盖板、人体面积/位置、走线及周边导体会参与测量 | 悬空可是真实可重复的电容信号，不全部当成随机噪声。原理参考[AN90071 §2.1–2.2](https://assets.infineon.com/is/content/infineon/infineon/row/public/documents/30/42/infineon-an90071-cy8cmbr3xxx-capsenser-design-guide-applicationnotes-en.pdf) |
| MPR独立通道阈值和原生迟滞可调，基线只公开高8位；原生ON为 `baseline-filtered > touch_threshold`，OFF为 `< release_threshold` | 逐键参数可用于有余量的弱悬空；可读差值带低2位未知区间，不能直接照抄页面数值。参考[NXP MPR121 §5.4/5.6](https://www.nxp.com/docs/en/data-sheet/MPR121.pdf) |
| MBR普通按钮DIFF范围0–255，寄存器是16位容器；DIFF经过归一化，不能等同RAW−BASE | 饱和信息无法靠扩大软件变量恢复。参考[MBR TRM §1.5.104](https://www.infineon.com/assets/row/public/documents/30/57/infineon-cy8cmbr3xxx-capsense-express-controllers-registers-trm-additionaltechnicalinformation-en.pdf)、[AN90071 §6.2.3](https://assets.infineon.com/is/content/infineon/infineon/row/public/documents/30/42/infineon-an90071-cy8cmbr3xxx-capsenser-design-guide-applicationnotes-en.pdf) |
| MBR FT范围31–200，HYS范围0–31；原生ON边界为FT+HYS | 最大231挡不住历史255悬空；现有400fF档已是最低灵敏度参数档，不能再虚构更低档或超范围配置。参考[AN90071 §5.2.1.3/6.2.1/6.2.2](https://assets.infineon.com/is/content/infineon/infineon/row/public/documents/30/42/infineon-an90071-cy8cmbr3xxx-capsenser-design-guide-applicationnotes-en.pdf) |
| 基线滤波是环境跟踪机制；它也可能跟进缓慢接近或持续接触。更长去抖/滤波会改变响应时间 | 不能通过吸收慢触、撤掉长按或延长等待制造“无隔空”。参考[NXP AN3891](https://www.nxp.com/docs/en/application-note/AN3891.pdf)、[MPR121 §5.7](https://www.nxp.com/docs/en/data-sheet/MPR121.pdf) |
| MPR寄存器写入一般要求Stop；MBR NVRAM有官方配置/CRC/保存/复位要求 | 不在扫描中周期停启整片或写MPR基线；不自行生成MBR 128B表。任何后续原生设置试验按原厂接口和逐片恢复执行 |

原厂强调SNR后再调参，但“信噪比好”与“接触/悬空可分”是不同条件：稳定悬空也可以具有高SNR。无物理SH屏蔽电极时，`SHIELD_EN`不是纯固件补救。

## 3. 本轮已执行：复合门控反例检查

新增 `tools/assess_touch_separation.py replay`，复用证据包内原始round90b分析脚本和当时的映射源码。先检查整个ZIP的SHA256、CRC、73个证据成员的大小/哈希；只执行固定哈希的原分析脚本，其他脚本作为数据。没有使用当前HEAD映射重解旧数据，也没有修改旧包。

回放14次已确认动作、1344个记录帧，得到9个接触标签动作首次ON、3个悬空首次ON、2个无首次ON的不可评估窗口；另保留并排除2个中止任务。这些是动作/主机记录数，不是独立原生扫描数、接触成功率或当前设备状态。

这次在单标量失败之上进一步检查：是否有一个悬空动作在所有“数值越大越容易放行”的特征上，都不弱于一个必须保留首次响应的接触标签动作。

| 原有首次final ON特征 | 慢触session13 | 慢触session14 | 悬空session12 |
|---|---:|---:|---:|
| 目标DIFF | 188 | 188 | 199 |
| 15–25ms平均增量/count·ms⁻¹ | 0.9375 | 0.882353 | 1.133333 |
| 30–40ms平均增量/count·ms⁻¹ | 0.454545 | 0.676471 | 1.21875 |
| 60–70ms平均增量/count·ms⁻¹ | 0.533333 | 0.483871 | 1.166667 |
| 过去100ms最大相邻有效读增量/count·ms⁻¹ | 2.4 | 3.0 | 6.2 |
| 同排曲率 | 376 | 376 | 398 |
| 高于128的格数 / 饱和格数 | 1 / 0 | 1 / 0 | 1 / 0 |

**裁决：幅值+短窗增量两项组合、以及上述六项组合均有2个慢触反例。** 因为悬空六项均更强，任何只使用这些特征、各维度单调递增放行的规则，只要保留这两次接触标签动作的原首次ON，就必须放行该悬空。单调AND/OR门限、非负加权评分以及单调幅值变换均属于这个范围；增加相同的格数/饱和数也不能区别这一对记录。

这是否决一类候选，不是否决全部算法。非单调历史结构、其他官方输入或新的测量信息不在此证明范围内；当前也没有证据支持它们能够安全泛化。首次ON未必就是物理触板时刻，既有标签只确认整组动作；裁决标准是保留已有首次响应，不把影子拒绝写成已实测贴面漏触。探索、预检和压力数据合并后只是反例筛查，不能重新称独立验证集。

机器可复核结果：`round90t_离线分离核查.json`。旧包SHA256为 `ef3c14945c4900537711ba2586c63a0a8599917cc532fe716a0b6773520c4e29`；工具和冻结解析方法的哈希随结果保存。

## 4. 本轮已执行：逐键余量筛选器

新增同一工具的 `margin` 子命令和输入模板 `round90t_逐键余量输入.json`。模板保存本次用户观察；缺少的字段保持null，12–16没有被填成已确认原生悬空上限。本轮运行得到 **unassessable**，没有产生可部署的阈值。

输入按板件、芯片、固件、配置哈希、逻辑格分别分层，不混算两个芯片或两个通道。每层需要：空闲上界、悬空上界、接触动作目标响应点的下界、轻触/长按保持下界、希望输出OFF时的释放尾段上界，以及明确选择的漂移余量。采集质量、新鲜度、原生尺度也必须明确；内部基线精度不足时传入区间。既有 `decode_mpr121_snapshot.py` 可解出MPR基线读回下界及3计数未知区间，不另造寄存器解码器。

筛选只计算抽象整数信号门限：`signal >= T_on`准入、`signal < T_off`释放，并要求 `T_off < T_on`：

```
max(空闲上界, 悬空上界) + 漂移余量 < T_on <= 接触响应下界 - 漂移余量
max(空闲上界, 释放上界) + 漂移余量 < T_off <= 保持下界 - 漂移余量
```

如果只需要降低部分悬空而非全部姿势，可先限定具体位置/姿势，保留未覆盖情况。上界/下界采用事先固定窗口和全部合格记录，不能挑选最好的一帧；目标响应点须有因果依据，不能事后移到信号峰值。手移到3mm仍要求OFF时，释放上界必须包含这段信号，不能只用彻底移远的零值证明释放安全。

这些是**信号可分性区间，不是硬件配置字节**。MPR原生ON比较为严格大于；本树软件验证还有 `sw-1`、强信号/邻格快路径。MPR逐键硬件阈值实际取 `max(全局, 逐键)`，固件参数限幅为63；MBR逐键字段是软件验证值，原生BUTTON_STAT另有配置，旧验证有80下限和邻格策略。任何区间必须映射到对应版本的实际生产路径并回放准入/保持/释放后，才能形成参数建议。工具即使找到区间，也固定返回 `deployment_ready=false`。

| P5 游戏验收 | 测试页退出、串口采样停止后，真实游戏比较悬空误触、轻触漏判、滑动断触和释放粘滞；独立复测冻结候选 | 用户手感和游戏结果优先；失败就恢复，不用更多保持/去抖补偿继续叠加 |

P1能力核对尤为必要：维护源码为beta14/round90r，最近文档中的原32寸对照是beta10/round90e，27寸则实际部署1.6.5-bootfix/round90r-1.6.5。这是仓库记录，**本轮未重新读取设备**；不能把HEAD产物直接刷到任一已恢复设备。beta10不支持MPR C6诊断；旧1.6.5也不能默认拥有后续完成帧记录器。按实际源码确定支持的接口，不向不支持的版本发送诊断命令。必要的新诊断应从实际验收基线分离，只记录、默认关闭，并量化额外总线/扫描开销。

普通模式模拟量若不足，优先复用Core0本轮已有测量和既有完成帧发布，而非Core1并发访问I2C。MPR单片43B原生一致窗和MBR35B SYNC差值组的用途不同；各芯片顺序读取不是同时采样。C6配置模式改变调度，不能以它证明普通模式手感。记录开启/关闭都要测扫描间隔、重试与最大开销；15ms配置延迟上限不是触板至HID总时延保证。

## 6. 可优先考虑和暂时排除的方向

| 方向 | 目前判断 |
|---|---|
| 逐键较高准入、合适释放迟滞 | 最直接的条件性方案；仅用于接触/悬空存在稳定余量的通道。MPR几乎无误触时不主动提高全板阈值；MBR饱和通道不适用 |
| 精确成功读取、禁止故障形成新ON、短故障有界保持 | 有价值的可靠性优化，但维护树已有round90d/e/n相关研究；必须先核对实际基线，不能把研究版整体部署或宣称它解决有效悬空ON |
| 灯光负载/刷新节奏 | 不改硬件也可做受控减轻，但目前只是可检验假设。持续可分的悬空信号不因滤掉随机尖峰而必然消失 |
| 原生滤波 | 原厂IIR/Median等可能降低噪声，需先见到噪声主导及延迟收益。稳定悬空和轻触同时被低通处理时，不保证接触分界改善；合法配置由官方工具/文档指引 |
| 启动与空闲校准 | 有助漂移维护，必须在确认无手/物体的维护窗口进行；不能把每次上电基线的变化当成抗悬空成效，不在游戏中周期重置整片 |
| 共模相减、空间宽度拒绝、学习软件基线 | 大面积真实按压与掌悬可能同样影响多格；历史四指平顶和慢触/长按反例必须先过，当前不进入输出算法 |
| 最小上升速度、幅值+速度单调组合 | 本轮两条复合反例已否决；不调门限后重算为成功 |
| 全板加去抖、长保持、NT吸收慢信号 | 会改变慢触、连打、释放或长按；当前不作为默认隔空方案 |
