## 记录方式

- Core0在原完成帧发布后复制已有240B C8结果。SDK `queue_t` 容量96，实际分配97×240=23,280B；SDK `critical_section` 保护控制请求及状态。初始化先于Core1。
- 默认OFF；ARM请求由下一次Core0发布确认并分配新session。未确认的ARM阻止旧会话读取。满队列丢最旧帧，明确累计overwritten；无需等待主机消费。
- 预热180ms后，当前及上一帧逐片VALID/COHERENT/BUTTON_VALID/READ_THIS_FRAME且rangeMask=0时，native/verified/final任一状态变化启动160ms后史。无效帧仍保存；不能把未捕获边沿当作没有触发。
- 10s无合格边沿自动停止；支持手动冻结，断连取消待ARM或停止已开始记录。独立取消latch覆盖ARM清空队列期间的断连交错。
- 冻结后不再追加；读取同一session中的帧。实际窗口长度和前史由帧时间检查，96帧不保证任何扫描速率下都有180ms前史。
- C8时间描述RP2040读事务和完成帧，不是原生芯片扫描时刻；三片顺序读取。提示音/动作确认不能提供准确贴面时刻，轻触下降过程可能已在悬空阶段触发。

## 追加协议

正常模式，无请求载荷。128B配置、原0xC8/0xB1/HID长度、API level均保持。

| 命令 | 回复 | 语义 |
| --- | --- | --- |
| C9 ARM | `[C9,accepted]` | accepted=1仅表示排队；轮询CC等待pending=0及新session |
| CA FREEZE | `[CA,accepted]` | 下一次Core0发布冻结；轮询CC确认 |
| CB READ | 248B `MbrHistoryFrame` | 仅冻结且无待控制时消费一帧；含session与原C8 |
| CC STATUS | 56B `MbrHistoryStatus` | 状态、pending、session、触发时间/帧、存入/覆盖计数、局部hook计时、容量及剩余 |

TX不足返回单字节0，FIFO完全满可无回复；CB不消耗记录，控制命令不排队。不发送半帧或等待空间。主机按BID/version门禁，一次一个事务。帧异常停止解析和后续事务，关闭连接触发记录取消。
