# MBR3116 算法与驱动重构计划：以 MPR121 替换实测为起点

2026-10-03。主维护树：`Nyanithm_firmware_hw_v1`；分支：`hw_v1_compatible`；规划前HEAD：`1902136`。

本文件始于设备断开时的round90c计划，随后执行进度见第9–11节。round90d/e已部署必要读取/故障修复并取得“手感正常，隔空仍存在”的反馈；round90f继续完成无需用户配合的原理与离线研究。当前没有已验证的抗悬空根治方案。

## 1. 新证据与根治目标

用户本次实测：将触控主控硬件换成MPR121后，不再出现隔空触发。这支持把重点移到 **MBR3116的测量/调谐/配置、模块电气条件及对应软件路径与面板的组合差异**；也说明现有电极面板至少能在一种实现下满足当前使用体验。

用户随后确认三片均换回MBR、除触摸模块外“其他未变”。这收窄了外部供电/装配等变化假设；模块自身电路、调谐和软件分支的差异仍须核查。目前缺少无隔空MPR的实际逐电极配置/信号快照，不从“换芯片有效”直接推导“重写RP2040算法必定根治”。

目标是消除日常隔空触发，保留轻触、慢触、连打、多押、slide、长按与触摸+Air。验收分三层：

- 测量：悬空是否产生原生BUTTON_STAT，DIFF是否饱和，基线怎样变化。
- 处理：native、verified、final、HID各在哪一步置位或释放。
- 体验：用户真实游戏误触、漏触、断触与手感。CDC干净不能替代HID验收。

## 3. 原理与可重写边界

覆盖板上的触摸通过电容变化间接检测，没有独立机械接触证明。人体面积、距离、位置、介质和接地共同影响信号。**MPR121本身也支持接近检测**，所以本次无隔空不能解释为它天然“只认接触”。[NXP MPR121 Datasheet](https://www.nxp.com/docs/en/data-sheet/MPR121.pdf)

MBR使用CSD PLUS测量及SmartSense调谐，原生基线/阈值/滤波形成状态。RP2040读到的是这条测量链的结果；128字节配置是设置，不能装入自定义芯片程序。重写RP2040驱动不会自动开放内部所有中间量。[MBR3 Datasheet](https://www.infineon.com/assets/row/public/documents/30/49/infineon-cy8cmbr3002-cy8cmbr3102-cy8cmbr3106s-cy8cmbr3108-cy8cmbr3110-cy8cmbr3116-datasheet-en.pdf)

| 输入能力 | MPR121 | MBR3116 |
|---|---|---|
| 信号 | 各通道10位滤波数据，可读基线是内部10位的高8位 | 普通按钮DIFF范围0–255，16位寄存器容器不扩大按钮范围 |
| 连续读取 | 官方支持多字节相关数据一致读取 | 全格DIFF可读一致组，不能假定全格RAW/BASE同样可读 |
| 深层诊断 | 各通道滤波值和基线 | RAW/BASE窗口由SENSOR_ID选单格，切换后需等实际刷新 |
| 参数复用 | 自身测量尺度 | 不照搬MPR的counts、差值方向、阈值或周期 |

依据：[MPR121 §5.3–5.4](https://www.nxp.com/docs/en/data-sheet/MPR121.pdf)、[MBR3 TRM Rev. E](https://www.infineon.com/assets/row/public/documents/30/57/infineon-cy8cmbr3xxx-capsense-express-controllers-registers-trm-additionaltechnicalinformation-en.pdf)。MBR差值缩放与基线的完整关系下一轮按原厂定义核查，不先假设等同未经缩放的RAW−BASE。

MBR按钮FT合法31–200、HYS为0–31，ON边界FT+HYS；最大231仍挡不住已有255悬空。ATH OFF只表示手动阈值，不能称关闭全部SmartSense。原厂Active刷新约束与主机轮询不同，约200Hz完成帧不是200Hz独立电极扫描。[AN90071 §6.2.2](https://assets.infineon.com/is/content/infineon/infineon/row/public/documents/30/42/infineon-an90071-cy8cmbr3xxx-capsenser-design-guide-applicationnotes-en.pdf)、[MBR3 Datasheet，Power States](https://www.infineon.com/assets/row/public/documents/30/49/infineon-cy8cmbr3002-cy8cmbr3102-cy8cmbr3106s-cy8cmbr3108-cy8cmbr3110-cy8cmbr3116-datasheet-en.pdf)

驱动可以改善读取语义、质量管理、时限和诊断；算法可以利用确实可取得的历史与状态。能否根治仍取决于输入有无可分信息。相同瞬时DIFF否决只靠该帧的严格分类，不证明所有历史或其他官方输入都无解。

## 6. 分阶段计划

### A. 原理与证据收敛——下一轮先做，可离线

1. 对照MBR TRM、AN90071、原厂Host API与MPR手册，画出物理量→测量→基线→公开寄存器→原生状态的链路。
2. 为每个可用输入登记单位/范围、饱和、有效条件、刷新约束、读取步骤、失败语义和实时成本。明确有无尚未利用、可实时全板取得的新信息。
3. 优先回放round89x、round89z、round90b；解释基线时再引入round89s。产出反例索引，不重复历史全套采集。
4. 对当前生产代码建调用图：MPR/MBR分支、profile与旧路径、验证/准入/保持/拉伸/slide及发布。

交付：原理对照、接口能力清单、反例目录、根因假设排序。进入下一阶段必须说明新增信息或可测机制，及为何旧反例尚未否决；没有新依据就停止同类调参。

### B. 最小必要的MPR/MBR对照——重新连接设备后

1. 识别实装芯片，不只看hwVer/配置位；核对地址、拓扑与固件路径。备份源码、UF2、控制器128B和可读芯片配置，记录哈希。
2. 保留当前无悬空MPR配置作参照。恢复MBR作为独立实验，记录模块/接线/装配差异，不覆盖参照数据。
3. 先选既有第17格，再按假设补长走线位置或跨芯片边界。固定覆盖板、供电、动作位置；只采能区分新假设的动作，含接近/轻触/手掌/慢触/多指。
4. MBR单格RAW/BASE走官方SENSOR_ID及刷新等待；全板DIFF/状态走已有完成帧诊断。标注非同时采样，不轮换32格RAW阻塞游戏循环。
5. 动作确认只标识整个动作；若要测触板到HID延迟，必须有独立物理触板和主机事件时间参照，提示页时间不能代替。

交付：同条件程度、测量链差异、根因排除表。若没有新增区分信息，不因MPR正常就直接批准全面重写MBR算法。

### C. 驱动契约与结构整理——先保持行为等价

首先整理src/cy8cmbr3116.cpp、src/hw_devices.cpp及其头文件。复用Pico SDK的I2C/计时/同步API、原厂Host API读组方式和现有有界重试；不fork SDK、不修改vendored库、不建通用冗余驱动框架。

按小提交依次实施：

- 读取契约：完整成功后才发布；区分短读/NACK/超时/SYNC失败。审查旧辅助函数是否失败后仍解码以及实际调用；保留严格读组和round89y延后重试，不把待审项宣称为悬空根因。
- 样本质量：区分本轮成功、可用旧值、读组一致、数值合法和年龄。rangeMask=1是合法；记录读取起止/发布时间。没有官方新扫描标识就不编造独立样本序号。
- 拓扑：沿用芯片/电极→32格映射；分清物理同排±2与游戏lane±1的用途，验证端点与跨芯片位置。
- 状态：拆清芯片专属证据判定与公共输出整理，采用最少函数/结构。每次整理用旧记录逐帧比较输出和边沿。
- 发布：HID/CDC共享同一完成快照；复用C8/C9–CC，额外记录默认关闭。协议/跨核发布独立审核，不先改128B配置布局。

交付：接口契约、行为等价diff、实际生产代码测试和时限记录。只有局部整理不能满足官方语义时才全面重写驱动；代码整洁不是根治证据。

### D. 新算法候选——有输入依据后再进入

目标顺序：**合格测量→芯片专属证据→每格准入/保持/释放→公共输出整形→同一快照发布**。读取故障与判断悬空是不同原因。已ON的故障释放/短时保持单独验收，不能无限粘住，也不能放行新ON。

| 方向 | 前提 | 必须覆盖的反例 |
|---|---|---|
| 原生测量/调谐修正 | 官方有相应接口，且恢复了未饱和可分裕量 | 单指/手掌接近、轻触、长按；仅改变BUTTON不够 |
| 多特征因果状态判定 | 实时可用历史/状态提供新信息，不是旧幅值/斜率重命名 | 慢触、快速悬空、相同255向量、多指平顶、slide及Air |
| 通道信号校正 | 稳定通道差异及可分裕量有证据 | 漂移、换手/位置、面积变化；不把信号标为毫米 |
| 软件基线/共模抑制 | 有足够新鲜的对应测量，并可区分环境变化与大面积接触 | 长按被吸收、多押误抑制、单指悬空；不假定全格RAW可用 |

状态须覆盖空闲、接近未准入、已准入、释放及读取故障。准入否决不能被强信号快路径、slide豁免或拉伸绕过；持续多押不能仅靠平顶/宽度撤销。

先影子计算并记录原因，保持原HID；冻结字段、参数和规则，再检查未参与选择的独立动作。优先确定性规则；小模型也必须经过相同输入/反例/成本门槛，不直接启动机器学习训练。

默认不加长确认窗口。若需等待新测量，应量化延迟代价并接受游戏验收。无可分输入时交付“根治条件未满足”，不部署分类器。

### E. 验证、部署和退回

验证矩阵包含：

- 中心、端点、跨芯片的食指/多指/手掌轻触、快点、慢触、长按及滑动。
- 静止和快速悬空，多个近面高度；手动估计高度如实注明。
- 多押、触摸+Air、LED变化、最终装回；供电/地参考实验只在对应假设需要时安排。
- 短读、NACK、SYNC不一致、旧值、profile切换、计时回绕和记录器开关。

用独立动作数/失败次数报告误触、漏触、断触、释放残留；帧数只说明采样质量。时延区分芯片刷新、I2C、处理和HID发布，记录典型、尾部与最大观察值，不能只报平均值。

## 7. 路线决策和停止条件

| 结果 | 后续行动 |
|---|---|
| 官方语义或模块电气不合规，并可复现影响 | 最小修复，重新验证测量和游戏表现 |
| 合法原生配置恢复全板可用裕量 | 优先原生方案配精简处理，不为重写而重写 |
| 历史联合信息通过独立反例及响应成本验收 | 实现可关闭的新判据，完成HID游戏验收 |
| 只改善限定手势 | 明列范围和残留误触，不称根治 |
| 无可用新信息，仍不可分 | 停止相同调参，保留已可用MPR；MBR根治所需模块/结构/新增接触证据另议，不自动改硬件 |

合法多押被吞、慢触不符合响应验收、长按被吸收、slide断裂或故障值被当新触摸，立即否决版本。声称触板后零漏触必须有物理触板时刻；只有整次动作确认时，不推算精确接触时刻。
