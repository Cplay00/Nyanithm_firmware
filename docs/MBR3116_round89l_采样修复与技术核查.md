# round89l 采样修复与技术核查

2026-10-01。用户确认食指轻触已完成，其他采样因程序提前结束未成功。保持已验收的round89g固件，先修复本地主机采样器，再核查用户提供的另一份技术结论。仅固件和现有寄存器路线的限制继续有效。

## 采样失败的实际原因及修复

本地文件共4次尝试：1次轻触已确认、2次3 mm悬空在预热中止、1次5 mm尝试有记录但重启核对失败且未获用户确认。后3次全部排除，不用未确认数据补齐高度标定。

两次3 mm预热最后8行各有一次`3116 debug fail`，8/8成功的准备判定过严，未进入4/8/10秒动作流程就恢复配置，提示却写成“采样结束”。改为以6秒循环窗口等待最近10行至少9行可读且末2行可读，原始失败行仍保留；持续失败则中止并恢复，不制造零信号。尚未开始动作时提示明确说明未采样，不开放成功确认。

5 mm尝试在重启后枚举检查与真正开口之间，设备短暂消失，报`target enumeration: []`。原重连包装只捕获串口异常，未覆盖这个精确竞态。现增加这类缺失枚举的重试，错误BID、多设备及其他异常仍立即拒绝。6秒/15秒是外层循环窗口，单次阻塞调用可使实际墙钟超出，不作为硬截止承诺。

设备已另行核对：控制器及三颗芯片配置与round89j备份逐字节相等，RAW=0、32格零，仍1.6.6-beta4/BID round89g。没有再次启用实验配置来修复网页。新服务载入已确认轻触历史，失败悬空组不进入成功列表；逐组原表恢复及重启核对继续保留。修前脚本及样本备份在`_dev_archive/round89l_sampler_before_20261001`。

轻触固定6.0–11.5秒窗口有42有效对、2次配对错误：中心RAW增量175–242，DIFF=255；12位Proximity邻格的RAW/BASELINE均2911、增量与DIFF均0。这个原生模式尚未给出有用的单指邻格参考，不能称距离抑制改善。先补同参数下有效3 mm悬空；若参考仍不响应，再单变量检查原表ALP滤波及其阈值，避免从常量拟合分类器。

## 对另一份结论的核查

“遵循原厂、降低总线开销、先调硬件阈值”是合理方向，以下关键断言需要修正。

|断言|官方接口和实测依据|对路线的影响|
|---|---|---|
|ATH_EN=0彻底关闭SmartSense|[KBA90796](https://community.infineon.com/t5/Knowledge-Base-Articles/Tuning-the-MBR3xxx-CapSense-Controllers/ta-p/248038)明确自动调谐与阈值接管分开；ATH只关闭自动阈值。|可以让手动FT生效，无法取得MPR式完整调谐自由度。|
|最低灵敏度、FT100–180可保证贴面|当前按钮已400 fF，原表FT200；[此前ATH OFF实测](MBR3116_round89d_ATH对照与后续路线.md)中，用户确认手掌约5 mm全程悬空，原生BUTTON_STAT仍ON，DIFF=255。|这套单纯阈值路线已有反例，降低FT不能解释为进一步缩短触发距离。|
|BUTTON_HYS写20–30%保证抬起利落|[TRM §1.5.26](https://www.infineon.com/assets/row/public/documents/30/57/infineon-cy8cmbr3xxx-capsense-express-controllers-registers-trm-additionaltechnicalinformation-en.pdf#page=57)是0–31计数字段。当前FT200的20–30%是40–60，超出范围；ON阈值为FT+HYS，OFF为FT−HYS。|大迟滞不能消除饱和悬空，还可能推迟释放；不能写非法值。|
|Driven Shield保证把20–30 mm压成1–2 mm|[AN90071 §2.6.1/4.2.1](https://assets.infineon.com/is/content/infineon/infineon/row/public/documents/30/42/infineon-an90071-cy8cmbr3xxx-capsenser-design-guide-applicationnotes-en.pdf#page=44)描述抗液体误触及近距增强用途。没有此定量压缩保证。|需要对应电极、连接及布局；尚未核实本板这些条件，不直接置SHIELD_EN。|
|MBR软件处理必然破坏既有1000Hz扫描|本板400kHz，现有门控每片以5ms间隔读35B含SYNC，而非每毫秒逐通道请求。round89g主循环实测约200Hz。|总线成本确实存在，但USB轮询、主循环与芯片刷新必须分开；不能由此断言软件处理不可行。|
|状态机不同就必然划键断连|[round89g修复](MBR3116_round89g_触摸刷新修复.md)实际定位全扫描seqlock使读者持续复用旧帧，改为完成帧发布后用户确认正常。|时序与快照实现是可验证原因；不把所有延迟都归于芯片状态机。|

仅计算I2C地址、寄存器与ACK位，35B STOP-write/read在400kHz每片约0.855 ms，三片约2.565 ms；2B状态读取每片约0.1125 ms、三片约0.3375 ms。均未含软件、等待、重试及其他外设开销，是线速下限，不能承诺完整固件<0.1 ms。减少DIFF读取频率或按需读取值得评估，但直接取消门控会重新暴露已实测的硬件悬空ON。

MPR121确有更多电流、充电时间及基线控制。[NXP Datasheet §3/5.1/5.11](https://www.nxp.com/docs/en/data-sheet/MPR121.pdf)同时说明它有自主滤波、基线、触摸判定和近距功能；基线写入通常需Stop Mode。“只有实际接触才可感应”“纯ADC由主机包办”都不准确。两款均测电容，面积与距离影响耦合，但平行板近似不能量化本板手掌高度或证明触碰。

## 新查到的原厂说明与后续计划

[KBA229990](https://community.infineon.com/t5/Knowledge-Base-Articles/Changing-resolution-of-CapSense-proximity-sensor-in-MBR3-does-not-decrease-scan/ta-p/250490)明确：Proximity内部始终按16位扫描，0x2E/0x2F的低分辨率配置对扫描后RAW作右移，`raw >> (16-resolution)`；降低分辨率不会缩短扫描时间。这修正我们此前“低分辨率先测扫描代价”的假设。分辨率配置合法、仍能影响输出与触发范围，但不能当作独立物理距离信息或加速扫描的手段。

1. **先补缺失对照。** 轻触已确认，下一组仅同指、同点约3 mm悬空，用尺子辅助手动估高。程序准备失败与有效姿势明确区分，固定时间窗、错误整对排除、恢复后确认。
2. **验证是否保留了弱参考。** 12位参考在本次轻触恒零；若悬空也恒零，按原厂ALP、噪声阈值及分辨率语义做单变量诊断，比较原生RAW与远离固定参考。调整的价值须来自新增可分裕量，不能来自计数变大本身。
3. **再谈实时与全板。** 每片仅CS0/CS1可Proximity，当前调试窗口仅单个选中电极，局部两个电极不覆盖32格。只在跨姿势可分后评估原生批量DIFF复用、读取预算与HID时序；C7固定等待不搬进游戏扫描。
4. **按证据限定距离标定。** 保留可调零/满信号点方向，不把计数线性换算为毫米；若不同面积/位置的接触和悬空仍重叠，说明这一输入组合不能可靠实现严格贴面判定，需要明确可达抑制与轻触代价。暂不重构未验证的128B表，也不部署无依据的面积规则。
