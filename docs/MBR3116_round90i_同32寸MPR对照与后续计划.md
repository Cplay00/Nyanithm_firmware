# round90i：同32寸PCB的MPR对照与后续计划

2026-10-04。同板部署、三片空闲、六组动作及独立游戏反馈已完成。用户游戏反馈“目前很稳定”，保持当前MPR设置；原生诊断中的轻触/多指异常仍待解释。本批没有新抗悬空算法，MBR隔空尚未解决。

## 1. 当前设备与保存结果

原32寸PCB、RP2040、覆盖板连接从27寸迁入的三片MPR模块。USB串号仍为`5303284739002C9C`，COM6，探测`bc0700050502`：0x5A/5B/5C MPR、无MBR、五ToF、HW2。模块外围也随模块迁移，差异不能全部归于芯片硅实现。

刷前beta10/round90e及控制器配置与迁移前一致；配置仍选择MBR，所以刚迁移时零输入不是MPR工作证据。已部署既有beta11/round90g诊断版，200704B，SHA256 `4412c8af403cba32125cc7135628b6c193d278cbfeeac944022ccfcad35f34d1`。392块元数据及唯一地址通过，写入`0x10000000..0x10018800`，未覆盖配置扇区。新版本仅增加配置模式MPR C6及版本标识，没有本轮新触摸管线。与27寸原round88d的比较仍有固件版本差异。

备份在工作区`_dev_archive/round90i_same32_before_20261004/`：原beta10 UF2/源码、控制器和三片旧MBR表。旧表来自迁移前快照，非当前硬件读回。`source_6010130.zip`是当前beta11源码；另保存`source_original_beta10_round90e.zip`及出处，避免与原UF2混配。本地UF2不是物理Flash镜像。

只改以下四字节，保留HW2/32灯/ToF/Air/高度偏移、RAW0和延迟0；没有整块复制27寸配置，也没有烧MBR表。

| 偏移 | 字段 | 原值→现值 |
|---|---|---|
| 3 | cfg0，MBR选择 | 0x02→0x00，使用MPR |
| 7 | 全局触摸阈值 | 12→13 |
| 8 | 全局释放阈值 | 10→12 |
| 127 | XOR | 0xA1→0xA4 |

阈值13/12取27寸全局参考，但32个逐键字段保持零、继承全局，不复制27寸少数15的覆盖。去抖0x11不变。测量调谐/阈值及驱动分支也有变化，本实验不是所有测量条件完全不变的芯片单变量试验。

首次host脚本误在B7后、B5前发B4；生产B4会从Flash重载RAM，不是RAM读取。校验因此中止，未保存。失败记录保留，修正为两个独立写的B7→B5→B4→CE→B9，不用129B合并写或CFG_SET轻推。保存返回`result: 0, currentPage = 10`，命令日志`b4b7b5b4ce`，保存及重启后128B均相等。当前配置SHA256 `d2b2cbe5ecb3f6dc625ed1c17e0e1672ebf688a2e5d5be7db2d08209c1f05596`。这次失败不能归因于sanitizer。

## 2. 三片空闲与实际增益

每片12次，共36个完整128B原生图像，无ON/OOR。CONFIG1/2为0x10/0x28，ECR0xCC：FFI6、SFI6、ESI1ms，名义更新6ms；12电极运行、Proximity关闭、CL3跟踪开启。dt1/dr1、ACE/ARE关闭，逐电极启动调谐仍生效；触摸/释放阈值均13/12。

| 地址 | 实际逐电极CDC | 实际CDT |
|---|---|---|
| 0x5A | 48–61µA | 全部1µs |
| 0x5B | 33–61µA | ELE0–10为1µs、ELE11为0.5µs |
| 0x5C | 36–48µA | ELE0–7为1µs、ELE8–11为0.5µs |

全局16µA/0.5µs不能代替实际增益。普通模式另读100帧CDC触摸全零、RAW0；这不是直接HID采集，也不能证明接近正确。

## 3. 六组原生证据与游戏反馈

用户完成9次采集，6次确认、3次作废；作废记录保留并排除结论。全部2194轮，确认1462轮，每轮三片128B、36电极，原图/通道字段/映射/顺序时间一致性校验通过。三片先后读取，43B信号组与85B参数窗也分开，不是跨片同瞬时真值或2194个独立扫描。倒计时及整次动作确认不是逐样本物理触板时刻。

本批三片一轮主机往返约90ms（首个确认动作中位89.76ms），远慢于芯片名义6ms更新。因此不能以未采到ON排除间隙内短暂ON，也不以这批主机采样验收连打或精确触摸延迟；持续保持窗的统计仍保留该采样边界。

沿用预设保持窗6–11.5s、晚窗9–11.5s。下表为确认动作的晚窗原生状态，不是游戏错误率。

|---|---|---|
| 第9竖条上半区轻触 | 0/28 | 无；整个有效hold85轮也全OFF |
| 第9竖条下半区轻触 | 27/27 | lane17＝0x5C ELE0 |

上半区轻触lane16：空闲filtered约715、可见baseline下界712；动作后filtered约694–699，但baseline跟到692–700，差值未超过门限。慢触同lane后段filtered约688、baseline704，差值下界约16，native ON保持。只从数据能确认基线跟进与响应差异，不能确认由硬件跟踪还是软件写入导致，也不能反推出力度或精确距离。

悬空未ON是本批结果，不代表没有电容耦合。手掌悬空的完整有效hold曾有个别lane可见差值下界14，不能只根据晚窗小值盲降全局阈值。本批四指和轻触参考尚有边界，不以静态幅值/面积/斜率拟合MBR新门控。

Finish记录确认双手远离，实际发送B9并关闭串口；随后普通命令响应确认设备回到正常模式。并发CDC观察曾占用设备，用户因此无法开始游戏；观察进程已结束，COM6短暂打开关闭成功，无命令发送。此后**游戏测试不再并发打开CDC**，也不再访问设备。用户独立游戏反馈“目前很稳定”。这是主观接受反馈，没有逐动作HID帧、漏触率或延迟量化；不能从诊断OFF直接宣布正常游戏同样漏触，也不能把游戏反馈改写为严格零误触。

## 4. 下一轮的实施顺序与停止条件

1. **先解释参考链。** 对照现有快/慢/四指的绝对filtered和baseline，确认物理位置/接触标签的边界及配置诊断与正常运行的观察差异。保持当前稳定MPR设置，不先增加去抖或临时降门限。
2. **审查并定位基线写入来源。** `hw_devices.cpp`既有MPR空闲纠偏约500ms轮询8电极；以rawTouch OFF、最近触摸/逐电极写入冷却2s及`3<diff<50`判断，可能调用`writeBaselineRun`向下写4/8 counts。native未过阈值的轻触也可能被当空闲，这是待验证假设。下一轮先按[NXP原厂资料](https://www.nxp.com/docs/en/data-sheet/MPR121.pdf)逐项复核CL、BVA、Run/Stop、NT/NNT过滤和写入返回，修正源码意图解释；现有C6没有写入事件旁证，不能直接归因。
3. **必要时加最小观测，分开修复。** 先提出能够分清硬件基线跟踪与软件纠偏的事件/前后值/有效状态证据。优先复用SDK与现有读取接口，预算扫描时序；新增协议/并发路径须备份、交叉只读审查、生产路径测试及构建。观测与行为改变分开提交，游戏验收时释放串口。
4. **再回到MBR可分信息。** 只有解释了MPR同板真实表现，才比较增益/归一化截断、native基线与模块外围。MBR仍受DIFF255饱和、RAW中心元组重合、合法多押平顶及慢触时间反例约束；不复制会吞慢触/轻触的基线策略，不重做已否决面积/斜率门限，不生成MBR128B表，不把ToF作为接触真值。

需要精细时序时优先审查并复用既有主控扫描侧有界记录机制，分清采样/基线写入/最终输入事件；游戏需要串口独占时，结束后才读回记录，不做并发CDC监视。先验证记录不改变扫描时序，再安排实机验收；不以约90ms的主机查询间隔构建新的响应门槛。

若参考采集与正常表现不一致，先修证据；若新方案吞慢触、合法多押、连打或slide，否决而非称作隔空根治。若现有电容信息仍不可分，停止重复调参，保留稳定MPR，另列所需原生测量或硬件条件。
