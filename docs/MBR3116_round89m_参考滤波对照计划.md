# round89m 参考滤波对照

2026-10-02。用户确认修复后的食指悬空3 mm组。保持round89g固件，先分析这组与已确认轻触，再准备仅关闭参考Proximity的ALP滤波对照。新实验尚未写入设备，需用户启动页面采样。

## 有效配对及恢复

两组均完整完成、用户确认、原表恢复并重启核对通过。控制器和三颗芯片的四块配置逐字节等于原备份；恢复快照RAW=0、32格零。旧的三个失败悬空尝试继续排除，不混入比较。

固定保持窗口6.0–11.5秒，错误整对排除，不填零：

|动作|有效对 / 错误对|中心RAW−BASE|中心DIFF|参考RAW−BASE / DIFF|
|---|---:|---:|---:|---:|
|食指轻触|42 / 2|175–242|255|0 / 0|
|食指约3 mm悬空|44 / 1|25–114|0–214|0 / 0|

参考为0x42:CS0，第18格；中心为0x40:CS7，第17格，依次通过原生C7读取。参考保持窗口RAW与BASE分别恒2911、2915，两组均不提供动作区分。中心单独在本次两组有61计数间隔，但不能推导全板门限：[此前相邻RAW对照](MBR3116_round89i_相邻RAW与后续实验.md)存在单指悬空与轻触重叠，另有已确认手掌悬空饱和反例。高度手动估计、位置仅一个、两组分开重启，不能将这86行当成86次独立触碰或全板验收。

## 单变量实验

原表的Proximity配置0x27=0x80，ALP开启；原表未启用Proximity，所以这不是普通按钮的ALP开关。[原厂TRM §1.5.31](https://www.infineon.com/assets/row/public/documents/30/57/infineon-cy8cmbr3xxx-capsense-express-controllers-registers-trm-additionaltechnicalinformation-en.pdf#page=62)定义bit7控制ALP。[AN90071 §6.3.1/6.3.2](https://assets.infineon.com/is/content/infineon/infineon/row/public/documents/30/42/infineon-an90071-cy8cmbr3xxx-capsenser-design-guide-applicationnotes-en.pdf#page=90)提供关闭ALP观察原始信号与噪声、再决定是否开启的调谐流程。ALP是参考恒零的待验证因素，尚未定位为根因。

基于实机原表及round89k的12位Proximity候选，只将0x27 bit7从1清为0，并更新原厂CRC。对比ALP ON候选，前126字节只有0x27变化；不改变分辨率、阈值、K值、ATH、引脚布局或其他芯片。相较普通原表，字节差异为：

|地址|原值|实验值|原厂定义|
|---|---:|---:|---|
|0x26|0x00|0x01|CS0/PS0 Proximity启用|
|0x27|0x80|0x00|ALP_FILTER_EN=0|
|0x2E|0x00|0x04|PS0输出12位|
|0x7E / 0x7F|C4 / 96|71 / 09|CRC=0x0971，小端|

原表SHA-256为`6535b3e1886f6359aab7cea09d1b8e2c6867b831ad2a1e4bd122affe8ecdb4e4`；候选为`75620d766ccd67e00bd5c2bb8b79ef4d086d840d076cdcea4ef51203ebd4a133`。具体字段与来源见[规格](MBR3116_round89m_ALP对照规格.json)。没有生成新的引脚/配置布局，也不将诊断Proximity模式用于游戏扫描。

每组沿用已验证的原生BA/C6/C7流程：先核对已备份原表，暂时应用候选并回读，准备窗口就绪后开始4秒远离、8秒动作、10秒远离；原表恢复、退出及重启后四配置回读全部通过，才开放用户确认。失败数据不替代成功数据；恢复不确定会阻止新组。C7诊断等待不进入固件实时路径。

新页`http://127.0.0.1:8770/`使用独立Origin和数据目录，默认食指轻触；旧8769已闲置关闭。下一步只完成同指同点轻触与约3 mm悬空各一组。若关闭滤波后参考出现可重复的弱信号，再对比信号、远离波动、不同面积与位置；若仍恒零，再评估分辨率量化等因素。只有显示计数变大不足以证明可分性。此次短窗不是原厂3000样本噪声调谐，尚不宣称SNR、严格贴面判定或毫米标定。
